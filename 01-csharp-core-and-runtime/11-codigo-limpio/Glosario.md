# Glosario

Las palabras que aparecen en las lecciones de esta carpeta, explicadas de forma simple. Están en orden alfabético.

-----

**Acoplamiento.** Cuánto depende una parte del código de los detalles de otra. Se busca que sea bajo.

**Azúcar sintáctico.** Sintaxis más corta que el compilador traduce a otra más larga, sin cambiar lo que hace.

**Buena práctica.** Forma probada de resolver un problema común.

**Code review.** Revisión del código por otra persona antes de integrarlo.

**Code smell ("olor").** Señal superficial en el código que suele indicar un problema de diseño más profundo.

**Código ceremonial (*boilerplate*).** Código repetitivo que no expresa lógica de negocio.

**Código limpio.** Código que se entiende rápido, se cambia con seguridad y no sorprende.

**Cohesión.** Cuánto se relacionan entre sí las responsabilidades de una misma clase o módulo. Se busca que sea alta.

**Deuda técnica.** Costo futuro de los atajos o decisiones subóptimas de hoy.

**DRY (*Don't Repeat Yourself*).** Cada pieza de conocimiento debe tener una única representación en el sistema.

**`.editorconfig`.** Archivo que define convenciones de estilo y nombres que el IDE y el compilador aplican a todo el equipo.

**`global using`.** Importación de un espacio de nombres que aplica a todos los archivos del proyecto.

**KISS (*Keep It Simple, Stupid*).** La solución más simple que resuelve el problema suele ser la mejor.

**`LangVersion`.** Propiedad del proyecto que indica qué versión de C# usa el compilador.

**Legibilidad.** Facilidad con la que una persona entiende el código.

**Número mágico.** Literal sin nombre cuyo significado no es evidente.

**Obsesión por primitivos.** Usar `string`, `int` o `decimal` para conceptos del dominio (email, dinero) en lugar de tipos propios con sus reglas.

**Refactoring.** Cambiar la estructura interna del código sin cambiar su comportamiento observable.

**Regla de tres.** Tolerar la duplicación hasta la tercera aparición antes de extraer una abstracción.

**Regla del boy scout.** Dejar el código un poco mejor de como lo encontraste.

**Sobreingeniería.** Diseño más complejo que el problema que resuelve.

**SOLID.** Cinco principios de diseño orientado a objetos: responsabilidad única, abierto/cerrado, sustitución de Liskov, segregación de interfaces e inversión de dependencias.

**YAGNI (*You Aren't Gonna Need It*).** No construyas lo que todavía no necesitas.
